4)
3. class Mammal {
4. String name = "furry ";
5. String makeNoise() { return "generic noise"; }
6. }
7. class Zebra extends Mammal {
8. String name = "stripes ";
9. String makeNoise() { return "bray"; }
10. }
11. public class ZooKeeper {
12. public static void main(String[] args) { new ZooKeeper().go(); }
13. void go() {
14. Mammal m = new Zebra();
15. System.out.println(m.name + m.makeNoise());
16. }
17. }
What is the result?
A. furry bray
B. stripes bray
C. furry generic noise
D. stripes generic noise
E. Compilation fails
F. An exception is thrown at runtime





Answer:
A is correct. Polymorphism is only for instance methods.
Fields do NOT support polymorphism

Reference type = Mammal
So: m.name → Mammal.name → "furry "

Instance methods
String makeNoise() { return "bray"; }

Methods support polymorphism
Method call is decided by object type

Object type = Zebra

So: m.makeNoise() → Zebra.makeNoise() → "bray"

Ans: B

Rules You MUST Remember (Very Important)
Static blocks
Execute once
Execute when the class is loaded
Parent class static blocks run before child class static blocks

Object creation order
When you do new B():
Parent class instance blocks
Parent class constructor
Child class instance blocks
Child class constructor

12)
class Box {
    int size;
}
class Test {
    static void swap(Box a, Box b) {
        Box temp = a;
        a = b;
        b = temp;
    }
    public static void main(String[] args) {
        Box x = new Box();
        Box y = new Box();
        x.size = 10;
        y.size = 20;
        swap(x, y);
        System.out.print(x.size + " " + y.size);
    }
}

Output?

A. 20 10
B. 10 20
C. 0 0
D. Compilation fails





Answer:  B
Reason: Java passes copy of references → swap fails.
